### 3. Sửa JPEG corruption warnings ✅

**Vấn đề:** Khi chạy lần đầu, console spam ~60 dòng "Corrupt JPEG data: extraneous bytes before marker".

**Nguyên nhân:** Alt setting = 7 (effective=1280 bytes) vừa khít minimum. Isochronous USB không retry khi mất packet → JPEG frame bị thiếu bytes.

**Cách xử lý (2 việc):**
1. **Thêm "comfort mode" cho alt selection** — ưu tiên alt setting có 2x bandwidth cần thiết (1280×2=2560 → chọn alt=10 với 2688 bytes). Kết quả: 0 JPEG warnings.
2. **Custom JPEG error handler** — dùng `setjmp/longjmp` để catch fatal errors, suppress non-fatal warnings. Frame lỗi bị skip thay vì crash.

---

### 4. Sửa RTSP push-buffer spam ✅

**Vấn đề:** Khi VLC connect rồi disconnect, console spam liên tục "push-buffer failed: -2".

**Nguyên nhân:** `-2` = `GST_FLOW_FLUSHING`. Khi client disconnect, GStreamer pipeline bị tear down nhưng code vẫn push frame vào appsrc đã chết.

**Cách xử lý:**
- Thêm `media-unprepared` callback: khi client disconnect → clear `appsrc = NULL`
- Trong `stream_push_frame`: nếu FLUSHING → clear appsrc, log 1 lần, ngừng push
- Client mới connect → `media-configure` callback tự set appsrc mới

---

### 5. VLC không kết nối được RTSP ⚠️

**Vấn đề:** VLC 3.0.20 hiện lỗi "satip stream error: Failed to play RTSP session".

**Nguyên nhân:** Module SAT>IP trong VLC chặn tất cả URL `rtsp://` trước khi module live555 xử lý.

**Giải pháp:** Dùng ffplay hoặc GStreamer client thay thế:
```bash
ffplay rtsp://127.0.0.1:8554/camera0
gst-launch-1.0 rtspsrc location=rtsp://127.0.0.1:8554/camera0 latency=0 ! decodebin ! autovideosink
```
→ Hoạt động tốt. Đây là bug của VLC, không phải driver.
