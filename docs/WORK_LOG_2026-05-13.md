### 1. Task B5 — Integration Test mycam.ko ✅

**Mục tiêu:** Xác nhận mycam.ko hoạt động end-to-end trên phần cứng thật.

**Quá trình (nhiều iteration do 3 bugs):**

**Bug 1: Secure Boot — "Key was rejected by service"**
- `insmod` bị từ chối vì module chưa enroll signing key vào UEFI MOK database
- Fix: `mokutil --import kernel/signing/MOK.der` → reboot → Enroll MOK qua UEFI shim
- Lesson: Module signing bắt buộc khi Secure Boot bật

**Bug 2: DMA Buffer — EAGAIN (-11) + Kernel Warning dump**
- `usb_control_msg()` return -11 kèm stack dump "Modules linked in:"
- Root cause: `mycam_uvc_probe_commit()` truyền **stack buffer** vào `usb_control_msg()`
- Kernel ≥5.x yêu cầu buffer phải DMA-safe (kmalloc'd), không phải stack variable
- Fix: Đổi `struct mycam_uvc_probe probe;` thành `probe = kmalloc(sizeof(*probe), GFP_KERNEL);`
- Lesson: Không bao giờ truyền stack/vmalloc buffer vào USB control transfer

**Bug 3: Return Value — "Inappropriate ioctl for device" (errno 26)**
- `usb_control_msg()` trả về **26** (= số bytes đã transfer) — giá trị positive
- VB2 framework coi bất kỳ return ≠ 0 là error
- Fix: Thêm `else ret = 0;` để normalize positive returns về 0
- Lesson: `usb_control_msg()` khác `ioctl()` — return byte count, không phải 0/error

### 2. Makefile Auto-Sign cho Secure Boot ✅

**Vấn đề:** Mỗi lần rebuild mycam.ko, module mất signature → insmod fail.

**Fix:** Thêm `sign` target vào `kernel/Makefile`:
```makefile
sign: mycam.ko
    $(KDIR)/scripts/sign-file sha256 $(SIGN_KEY) $(SIGN_CER) mycam.ko
```

Giờ `make` = build + sign tự động.

## Bài Học Rút Ra

1. **usb_control_msg() cần DMA-safe buffer** — Stack variable gây WARN + EAGAIN trong kernel ≥5.x. Luôn dùng kmalloc.

2. **usb_control_msg() return convention** — Trả byte count (positive) khi thành công, negative errno khi fail. KHÁC với ioctl (trả 0/-1). Phải normalize.

3. **Secure Boot workflow** — Out-of-tree module cần: (1) Tạo key pair, (2) sign-file sha256, (3) mokutil --import, (4) Reboot + Enroll MOK. Makefile phải auto-sign sau mỗi build.

4. **usb_autopm_get_interface cần supports_autosuspend** — Nếu driver không set `.supports_autosuspend = 1`, USB core sẽ `pm_runtime_disable()` interface → `usb_autopm_get_interface()` return EACCES. Đừng dùng autopm nếu không implement suspend/resume callbacks.
